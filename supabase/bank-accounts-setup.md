# หลายบัญชีรับเงินต่อร้านค้า

รัน `bank-accounts.sql` หลัง `platform-dashboard.sql` ก่อนใช้โค้ดรุ่นนี้ มีการย้ายบัญชีเดิมที่ข้อมูลถูกต้องเข้า `bank_accounts` อัตโนมัติ เก็บเลขเป็น string เพื่อรักษาเลขศูนย์นำหน้า รันซ้ำไม่คืนบัญชีที่ปิดหรือลบแล้ว

ในหน้า `/slips?tab=settings` เพิ่ม แก้ไข ลบ และเปิด/ปิดบัญชีได้ เจ้าของร้านกับ Admin จัดการได้ พนักงานอ่านได้เท่านั้น มี RLS ป้องกันการเข้าถึงบัญชีข้ามร้าน

SlipOK API ไม่มีพารามิเตอร์รายการบัญชีปลายทาง ระบบจึงตรวจสลิปผ่าน API แล้วเทียบธนาคารและเลขบัญชีกับ **บัญชีที่เปิดใช้งานของร้านนั้น** ฝั่งเซิร์ฟเวอร์ ทั้งการตรวจด้วยมือและ webhook ใช้ `processSlip` เดียวกัน พร้อมเพย์ใช้ receiver proxy ถ้าไม่มีบัญชีเปิดอยู่ ระบบไม่เรียกตรวจสลิปและไม่ตัดโควตา

กรณี SlipOK ตอบ 1014 พร้อมข้อมูลสลิปเพราะผู้รับไม่ตรงบัญชีหลักของสาขา ระบบยังตรวจผู้รับกับบัญชีของร้าน และตรวจยอดเงินตามออเดอร์ สถานะ fake/duplicate/error ไม่ถูกเปลี่ยนเป็น valid ตาม [เอกสาร SlipOK](https://slipok.com/api-documentation/check-slip/)

บัญชี active รายการแรกยังสะท้อนในฟิลด์บัญชีเดิมของ tenants เพื่อใช้ในข้อความแจ้งชำระเงิน CF บัญชีที่ปิดจะไม่ถูกแจ้งให้โอน การตั้งค่าบัญชีรับเงินของแพลตฟอร์มสำหรับซื้อแพ็กเกจ/เติมเครดิตยังใช้ค่าตั้งค่าฝั่งแพลตฟอร์มเดิม

บัญชีเดิมที่ชื่อว่างจะใช้ชื่อร้านให้แก้ไขต่อในหน้าตั้งค่า เลขบัญชีที่ไม่ใช่ 10–15 หลักจะไม่ถูกนำเข้าอัตโนมัติ ให้เพิ่มข้อมูลที่ถูกต้องในรายการบัญชีใหม่

```powershell
node scripts/test-bank-accounts-sql.cjs <path-to-@electric-sql/pglite>
node scripts/test-slip-order-total.cjs
node scripts/test-slip-settings.cjs
npm.cmd run build
```
