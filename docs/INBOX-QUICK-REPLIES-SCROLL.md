# คำตอบด่วนและการเลื่อนห้องแชท

อัปเดต Saved Replies: ใช้ native Dialog กลางจอแทน Popover มีรายการคำตอบ/ฟอร์ม Shortcut (ไม่เกิน 60 ตัวอักษร)/Message Body พร้อมตัวนับ 2,000 ตัวอักษรและปุ่มบันทึก/ยกเลิก รองรับมือถือและไม่ส่งข้อความเอง เลือกคำตอบแล้วปิด Dialog พร้อมกลับช่องพิมพ์เหมือนเดิม

**หากเคยติดตั้ง SQL แล้ว ให้รัน `supabase/inbox-quick-replies.sql` ฉบับล่าสุดอีกครั้ง** เพื่อเพิ่มคอลัมน์ `shortcut` และ RPC แบบห้าพารามิเตอร์ รายการเก่าคงเดิม และ RPC แบบสี่พารามิเตอร์ยังเรียกได้ผ่าน wrapper ไม่ต้องลบตารางหรือข้อมูล ปัจจุบันบันทึกเฉพาะข้อความ ส่วนสื่อให้แนบจาก Composer หลังเลือกคำตอบ

## ติดตั้ง

รัน `supabase/inbox-quick-replies.sql` ใน Supabase SQL Editor หลังติดตั้ง `smart-inbox.sql` เดิม ไฟล์นี้เพิ่มเฉพาะตาราง `inbox_quick_replies` และ RPC `save_inbox_quick_reply` ไม่แก้ข้อมูลลูกค้า ข้อความ ออเดอร์ หรือกฎบอท และไม่ได้ถูกรันกับฐานข้อมูลจริงระหว่างพัฒนา

เปิดคำตอบด่วนในแถบพิมพ์ → **+ เพิ่มคำตอบด่วนใหม่** → พิมพ์ → **บันทึก** → เลือกรายการที่เพิ่มเพื่อแทรกตรงเคอร์เซอร์ ตรวจทานแล้วค่อยส่ง ระบบไม่ส่งข้อความเอง

คำตอบจากกฎร้านเดิมยังอยู่ รายการที่เพิ่มใหม่แยกเก็บจากกฎบอทเพื่อไม่ให้เกิดการตอบอัตโนมัติโดยไม่ได้ตั้งใจ สูงสุด 100 รายการต่อร้าน ข้อความไม่เกิน 2,000 ตัวอักษร และจำกัดการบันทึก 30 รายการต่อนาทีต่อผู้ใช้

ถ้ายังไม่ติดตั้ง SQL จะบันทึกถาวรไม่ได้และมีข้อความผิดพลาดให้ลองใหม่ รายการเดิมจากกฎร้านยังเลือกใช้งานได้

## ไฟล์และ API

- `QuickRepliesMenu.tsx`: เพิ่มรายการ โหลดข้อมูลร้าน บันทึกแล้วแสดงทันที ป้องกันกดซ้ำ และเก็บ request ID เดิมเมื่อ retry
- `ReplyBox.tsx`: ส่ง tenant ให้เมนู โฟกัสช่องพิมพ์แบบ preventScroll และกระชับ padding
- `GET/POST /api/inbox/quick-replies?tenantId=...`: ตรวจ session/tenant/แพ็กเกจ ผ่าน guard เดิม ตรวจ cross-site POST และใช้ RPC ที่ตรวจสิทธิ์ซ้ำ
- Migration เปิด RLS และให้เฉพาะ service role ผ่าน API เข้าถึงตาราง/RPC

## แก้ Scroll และเพิ่มพื้นที่

- แทน `scrollIntoView` ด้วย `useChatScroll.ts` ซึ่งแก้เฉพาะ scrollTop ภายใน Message List
- เปิดแชทที่มีข้อความแล้วเริ่มที่ท้ายแชท หากยังซ่อนอยู่บนมือถือ จะทำเมื่อกรอบแชทแสดงจริง
- ขณะอยู่ท้ายแชทติดตามข้อความใหม่และความสูงรูปภาพผ่าน ResizeObserver
- ขณะอ่านย้อนหลัง จด message ID และ offset ของข้อความแรกที่มองเห็นเพื่อรักษาตำแหน่งเมื่อข้อความเก่า/ข้อความใหม่/ขนาดเนื้อหาเปลี่ยน
- หลังส่งสำเร็จ กลับท้ายแชทอย่างชัดเจน ไม่ใช้เงื่อนไขว่าข้อความท้ายสุดเคยเป็นของแอดมิน
- ยกเลิก browser scroll anchoring เฉพาะกรอบข้อความเพื่อไม่ให้ชนกับการรักษาตำแหน่งของ hook
- `/inbox` ใช้พื้นที่ flex ที่เหลือจริงแทน h-full และ shell ไม่เลื่อนทั้งหน้าเฉพาะ route นี้ หน้าอื่นยังเลื่อนตามเดิม

## ตรวจสอบและย้อนกลับ

ทดสอบ API/SQL/Realtime รวม 23 รายการใน isolated database/mock provider ไม่มีการส่งข้อความจริง Browser fixture ทดสอบสร้างคำตอบด่วน/แทรกข้อความ ประวัติยาว incoming/prepend การตามท้ายแชท การสลับห้องและ outer scroll พร้อมขนาดหน้าจอ 375/768/1440

การย้อน UI ไม่ต้องลบตาราง เก็บข้อมูลคำตอบด่วนไว้ได้ หากจำเป็นต้องถอน schema ต้องสำรองตารางใหม่ก่อน แล้วถอนเฉพาะ RPC/table ใน `inbox-quick-replies.sql` ห้ามลบตาราง messages หรือ chat_rules เพื่อย้อนงานนี้
