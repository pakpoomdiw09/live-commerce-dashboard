# ตั้งค่าระบบดูดออเดอร์ไลฟ์สด

หน้า `/live-cf` รับลิงก์วิดีโอ Facebook แบบเต็ม เช่น `/ชื่อเพจ/videos/123...`, `/watch/?v=123...`, `/watch/live/?v=123...` และ `/video.php?v=123...` เมื่อวางลิงก์หรือออกจากช่องกรอก ระบบจะเปลี่ยนเป็นรหัสให้ทันที ยังรองรับรหัสตัวเลขและ `เพจ_โพสต์` เดิม การเว้นว่างหมายถึงรับทุกไลฟ์ของเพจ ลิงก์ย่อ `fb.watch` และลิงก์แชร์ที่ไม่มีรหัสตัวเลขจะให้คัดลอกลิงก์วิดีโอแบบเต็ม ไม่เดารหัสจากข้อความในลิงก์

กด “เพิ่มสินค้าใหม่เข้าเซลล์เพจ” ข้างช่องเลือกสินค้าเพื่อกรอกรหัสสินค้า ชื่อ หมวดหมู่ ราคาขาย รายละเอียด สต็อก สถานะเปิดขายและสินค้าแนะนำ อัปโหลดรูปได้ 8 รูป และเพิ่มตัวเลือกได้ 40 รายการ พร้อมรหัส CF ราคาและสต็อกแยกตามตัวเลือก ไม่แสดงช่องต้นทุนหรือราคาเปรียบเทียบ

หน้าต่างกว้าง `max-w-3xl` เลื่อนดูฟอร์มได้โดยหัวข้อและปุ่มบันทึกยังอยู่ในหน้าต่าง สต็อกรวมคำนวณจากตัวเลือกย่อยให้อัตโนมัติ บันทึกสำเร็จจะเลือกสินค้าและตัวเลือกแรก เติมรหัสจอง และแสดงรูป/ราคา/สต็อกในสรุปโดยไม่โหลดหน้าใหม่ สามารถเปลี่ยนตัวเลือกในหน้าไลฟ์ได้ทันที หากปิด “เปิดขาย” จะบันทึกสินค้าไว้ แต่ยังเริ่มรับออเดอร์ของสินค้านั้นไม่ได้

## ไฟล์ที่เกี่ยวข้อง

| ไฟล์                                        | หน้าที่                                                                           |
| ------------------------------------------- | --------------------------------------------------------------------------------- |
| `components/live-cf/LiveCfSetup.tsx`        | หน้า Tailwind, รายการสินค้าที่เพิ่มระหว่างใช้งาน, การเลือกสินค้าและสรุปการตั้งค่า |
| `components/live-cf/QuickProductModal.tsx`  | หน้าต่างเพิ่มสินค้า การตรวจฟอร์ม สถานะบันทึก ข้อผิดพลาด และป้องกันกดส่งซ้ำ        |
| `lib/features/commerce/live-cf-setup.ts`    | อ่านรหัสจากลิงก์ ตรวจข้อมูลสินค้า และแปลงคำแทนข้อมูลภาษาไทยสำหรับข้อความตอบกลับ   |
| `lib/features/comments/live-products.ts`    | โหลดสินค้าของร้านพร้อมที่อยู่เซลเพจ รวมกรณีร้านยังไม่มีสินค้า                     |
| `app/(dashboard)/live-cf/page.tsx`          | ส่งข้อมูลร้านและที่อยู่เซลเพจให้หน้าตั้งค่า                                       |
| `app/api/live-cf/setup/route.ts`            | ตรวจลิงก์หรือรหัสซ้ำฝั่งเซิร์ฟเวอร์ก่อนบันทึกกฎ                                   |
| `app/api/commerce/product-options/route.ts` | โหลดหมวดหมู่ของร้านผ่านสิทธิ์เจ้าของร้าน โดยไม่โหลดข้อมูลออเดอร์หรือรายงาน        |
| `components/shop/ProductImageGrid.tsx`      | ใช้ชุดอัปโหลดและพรีวิวรูปเดียวกับหน้าร้านค้า                                      |

การเพิ่มสินค้าใช้ `POST /api/commerce` เดิมด้วย `action: product` ซึ่งตรวจเจ้าของร้าน ต้นทางคำขอ ข้อมูลสินค้า จำนวนรายการตามแพ็กเกจ และรหัสซ้ำ ก่อนเรียก `commerce_save_product` ให้บันทึก `products` และ `commerce_variants` ใน transaction เดียว กำหนด UUID ของตัวเลือกก่อนส่ง เพื่อให้หน้าไลฟ์เลือกตัวเลือกด้วยรหัสที่ตรงกับฐานข้อมูลทันที ไม่ใช้ service key ใน browser

หมวดหมู่โหลดจาก `commerce_categories` โดยกรอง `tenant_id` และแบ่งหน้าให้ครบ แล้วรวมหมวดหมู่มาตรฐานแบบเดียวกับหน้าร้าน หากโหลดไม่สำเร็จสามารถลองใหม่ได้โดยไม่เสียข้อมูลฟอร์ม รูปส่งไป `POST /api/commerce/media` เดิม ซึ่งตรวจไฟล์และสิทธิ์ก่อนแปลงภาพเป็น WebP แล้วเก็บใน Supabase Storage bucket `comment-media` ที่ `commerce/{tenantId}/...` URL ของรูปบันทึกใน `products.commerce_images` และรูปแรกใน `products.image_url` ตามโครงสร้างเดิม ไม่ต้องสร้างตารางรูปหรือ migration เพิ่ม ปุ่มบันทึก/ปิดจะรอจนการอัปโหลดเสร็จ

รหัส CF จากฟอร์มบันทึกลง `products.code` ซึ่งเป็นคอลัมน์รหัสสินค้าจริงของโปรเจกต์นี้ ค่าเริ่มต้นคือเปิดขายและ `commerce_archived: false` เพื่อให้สินค้าแสดงในเซลเพจโดยอัตโนมัติเมื่อเปิดหน้าร้านและมีส่วนรายการสินค้าอยู่แล้ว ไม่เปิดหน้าร้านที่ปิดอยู่แทนผู้ใช้ ต้องเปิดระบบร้านค้าและจัดการสินค้าเดิม (`NEXT_PUBLIC_SALES_PAGE_V2_ENABLED=true` และไม่ตั้ง `PRODUCT_MANAGER_V2_ENABLED=false`)

ข้อความบนหน้าจอใช้ `{ชื่อสินค้า}`, `{ราคา}`, `{ตัวเลือกสินค้า}`, `{ยอดชำระ}` และ `{ลิงก์ชำระเงิน}` โดยแปลงกลับเป็นคำแทนข้อมูลภาษาอังกฤษเดิมก่อนบันทึก จึงยังส่งข้อความผ่านระบบเดิมได้และเปิดแก้ไขข้อความเก่าได้

## ตรวจสอบ

```powershell
npx.cmd tsc --noEmit
npm.cmd test
node scripts/check-live-cf-setup-browser.cjs
```

ชุดทดสอบ browser ใช้ Chrome บน Windows รันหน้า React จริงพร้อม Tailwind ที่สร้างจากโค้ดล่าสุด ทดสอบ URL, หมวดหมู่/โหลดใหม่, อัปโหลดรูป/ลองใหม่, ตัวเลือกและสต็อกรวม, การรักษาข้อมูลเมื่อบันทึกไม่ผ่าน, ป้องกันกดซ้ำ, การเลือกสินค้าพร้อมตัวเลือกทันที และหน้าจอ 375/768/1440 พิกเซล ภาพตรวจสอบอยู่ใน `.tmp/live-cf-ui/` การทดสอบใช้ API จำลองและฐาน PGlite ไม่สร้างสินค้าหรือส่งข้อความไปยังร้านจริง
