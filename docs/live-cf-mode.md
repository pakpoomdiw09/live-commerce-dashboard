# โหมดไลฟ์สดในชุดตอบกลับคอมเมนต์

หน้า `/comment-replies/new` และหน้าแก้ไขกฎมีสองโหมด: ตอบกลับคอมเมนต์ทั่วไป และ Live CF กฎเดิมเริ่มเป็น `general` เสมอ ไม่มีการเปิดขายอัตโนมัติให้กฎเดิม

ในโหมด Live CF เลือกสินค้าจาก `products` ของร้านที่กำลังจัดการ หากสินค้ามีสี/ขนาด ให้เลือก `commerce_variants` ด้วย ตั้งรหัสอิสระได้หลายรหัสต่อกฎ เช่น `159`, `A1`, `Z99` โดยไม่เปลี่ยน SKU ของเซลเพจ รหัสรองรับภาษาอังกฤษ ตัวเลข `_` และ `-` ไม่เกิน 40 ตัว ไม่แยกตัวพิมพ์ใหญ่เล็ก เลือกตรงทั้งข้อความหรือคีย์เวิร์ดแยกคำได้ `A1` ไม่ตรงกับ `A12` หรือ `BA1` คอมเมนต์หนึ่งสร้างสินค้าหนึ่งชิ้น หากตรงหลายกฎจะไม่เดาว่าต้องสั่งสินค้าไหน

เลือกตัดจากสต็อกหลัก หรือกำหนดเพดานขายต่อกฎไลฟ์ได้ ทั้งสองแบบตัดสต็อกหลักจริง ไม่สร้างสต็อกเพิ่ม จำนวนที่ใช้ไปนับออเดอร์ของกฎที่ยังไม่ยกเลิก การปิดแล้วเปิดกฎไม่รีเซ็ตจำนวน หากต้องการเปลี่ยนสินค้าในกฎที่มีออเดอร์แล้ว ต้องสร้างกฎใหม่ การยกเลิกใช้ trigger เดิมคืนสต็อกสินค้า/ตัวเลือกและคืนสิทธิ์ในเพดานขาย

## การติดตั้ง

รัน `supabase/live-cf-mode.sql` ใน Supabase SQL Editor **หลัง** `comment-rules.sql`, `platform.sql`, `commerce-v2.sql`, `live-cf-variants.sql` และ migrations ของระบบบัญชี/QR ที่ใช้งานอยู่ SQL รันซ้ำได้และรักษากฎทั่วไปเดิม เพิ่มคอลัมน์โหมด/สินค้า/เพดานขาย และ RPC `place_live_cf_order` ที่เรียกได้เฉพาะ `service_role` พร้อมตรวจร้านค้า เพจ ลูกค้า สินค้า และตัวเลือกฝั่งฐานข้อมูล

การทดสอบในเครื่องใช้ฐานข้อมูล PGlite แยก ไม่ได้รัน migration บน Supabase จริง หากไม่มี `DIRECT_URL`/`DATABASE_URL` ต้องนำ SQL ไปรันเองก่อน deploy โค้ดที่อ่านคอลัมน์ใหม่ ไม่ต้องเพิ่ม environment flag สำหรับโหมดนี้

## Webhook และการชำระเงิน

ตัวรับ webhook รองรับทั้ง `live_comments` และคอมเมนต์ `feed` โดย normalize ชื่อ `id`/`comment_id` และ `video_id`/`post_id` ก่อนบันทึกในคิว เหตุการณ์สองรูปแบบของคอมเมนต์เดียวกันใช้กุญแจกันซ้ำเดียวกัน รับเฉพาะคอมเมนต์ใหม่และข้ามข้อความของเพจเอง

หากระบุรหัสโพสต์/วิดีโอในกฎ จะรับเฉพาะโพสต์นั้น ถือเป็นการระบุไลฟ์โดยร้านโดยตรง รองรับทั้ง `videoId` และ `pageId_videoId` หากเว้นว่าง จะต้องเป็น `live_comments` หรือคอมเมนต์ feed ที่ Graph API ยืนยันว่าเป็นวิดีโอสถานะ `LIVE` เท่านั้น อ่านข้อมูลวิดีโอเมื่อมีรหัสตรงกับกฎ Live CF แล้ว ไม่ polling และไม่อ่าน Graph สำหรับคอมเมนต์ทั่วไป หาก Meta ไม่อนุญาตให้อ่าน จะไม่เดาว่าโพสต์ทั่วไปเป็นไลฟ์

การเชื่อมเพจเดิม subscribe `feed` อยู่แล้ว ต้องเปิด webhook ของแอปและให้สิทธิ์เพจที่จำเป็นสำหรับอ่านวิดีโอ/คอมเมนต์ ส่ง private reply และ public reply ทดสอบจริงกับเพจที่เชื่อมก่อนเปิดใช้งาน ลูกค้าต้องอนุญาตรับข้อความและเพจต้องมี token ที่ยังใช้งานได้

`onComment` เลือกกฎ Live CF ที่เปิดอยู่ในร้าน/เพจนั้น เรียก `placeCfOrder({ source: 'live_comment', ... })` ผ่าน RPC ใหม่ ธุรกรรมเดียวล็อกสินค้า/ตัวเลือก ตรวจเพดานขาย ตัดสต็อก และเพิ่ม `orders` สถานะ `pending_payment` พร้อม `live_rule_id`, `source_id` และรหัสที่ลูกค้าใช้ คอมเมนต์เดิมไม่สร้างออเดอร์หรือตัดสต็อกซ้ำ สต็อกเป็นแถวเดียวกับที่ storefront checkout ใช้ จึงไม่ขายเพิ่มจากสำเนาสต็อกเก่า

Private Reply ใช้ `recipient.comment_id` ของคอมเมนต์และ token ของเพจนั้น ไม่เอา UUID ลูกค้าไปเป็น PSID และไม่ใช้ MESSAGE_TAG เพื่อเปิดแชทใหม่ ส่งยอดค้างจริงพร้อมรูป QR ปัจจุบันของบัญชีหลักที่เปิดใช้งาน โดยตรวจ snapshot บัญชีและสร้าง signed URL ชั่วคราว หากไม่มี QR จะส่งรายละเอียดบัญชี หากยังไม่มีบัญชีหลักจะแจ้งให้รอแอดมิน ระบบไม่อ้างว่าส่ง QR แล้วในกรณีที่ไม่มีรูป

Public Reply ยืนยันหลัง Private Reply สำเร็จ หากส่งล้มเหลว ออเดอร์และสต็อกไม่ถูกย้อนกลับ คิวใช้กลไก review เดิมเพื่อไม่ยิงซ้ำเมื่อผลส่งไม่แน่นอน การส่งทั้งสองแบบยังใช้โควตาข้อความเดิม กฎทั่วไปไม่สร้าง CF order อีกต่อไปจากการพิมพ์ SKU โดยไม่มีการตั้งกฎ Live CF

ออเดอร์ Live CF อยู่ใน `orders` เช่นเดียวกับ CF จากแชท จึงเชื่อมกับ `pendingOrders` และการตรวจสลิปอัตโนมัติเดิม ไม่คัดลอกไปสร้างออเดอร์ซ้ำใน `commerce_orders` ซึ่งเป็น checkout ของเซลเพจ

## Realtime และผลกระทบ

แท็บสินค้าร้านค้า V2 subscribe เฉพาะ `products` และ `commerce_variants` ของ tenant ที่เปิดอยู่ แก้เฉพาะจำนวนและ version ในหน้าจอ ไม่โหลด dashboard aggregate ซ้ำทุกคอมเมนต์ ใช้ snapshot ขนาดเล็กเฉพาะสินค้าในหน้าปัจจุบันเมื่อเชื่อมต่อหรือกลับมาเปิดแท็บ ยกเลิก channel และ abort snapshot เมื่อซ่อนแท็บ เปลี่ยนร้าน/หน้า หรือออกจากหน้า ไม่มี interval เพิ่ม

SQL เพิ่มสองตารางนี้ใน publication `supabase_realtime` ถ้ามี publication อยู่แล้ว โดยยังใช้ RLS เดิม Legacy shop ใช้ LiveRefresh เดิม ส่วนหน้าร้านสาธารณะอ่านสต็อกล่าสุดเมื่อเปิดหน้า และ checkout ตรวจสต็อกจริงทุกครั้ง หน้าจอสาธารณะที่เปิดค้างไม่ได้เพิ่ม Realtime subscription

```powershell
node --test scripts/test-live-cf-mode.cjs

node scripts/check-live-cf-browser.cjs
```

เทสครอบคลุม migration ซ้ำ การแยกร้าน/เพจ/สินค้า/ตัวเลือก รหัสอิสระ เพดานขาย สต็อกไม่ติดลบ การยกเลิกคืนสต็อก replay คอมเมนต์ การส่ง QR/public reply และ cleanup/snapshot race ของ Realtime พร้อม regression ของคิว webhook สลิป คอมเมนต์ทั่วไป การจัดการร้านค้า และ Meta client ทดสอบด้วยข้อมูลจำลอง ไม่ส่งข้อความจริงหรือหักสต็อกบน Supabase จริง

Browser test ใช้ RuleEditor จริงใน Chrome/Strict Mode ตรวจสร้าง/แก้ไข เลือกสินค้าและสี รหัสอิสระ เพดานขาย/สต็อกร่วม สลับกลับโหมดทั่วไป ป้องกันคลิกซ้ำ และความกว้าง 375/768/1440 ภาพตัวอย่างอยู่ใน `docs/screenshots/live-cf-mode-*.png`
