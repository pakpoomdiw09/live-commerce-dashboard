# แก้เงื่อนไขผู้รับบรอดแคสต์

สาเหตุในโค้ดเดิม: `bot_enabled=false` หรือ `conversation_status=closed`
ถูกแปลเป็นการพักรับบรอดแคสต์ ทั้งที่ Inbox ใช้ค่าเหล่านี้ตอนรับช่วงแชท
ส่งต่อเจ้าหน้าที่ พักบอท หรือปิดงานด้วย ไม่ใช่การยกเลิกรับข้อความของลูกค้า

แก้ทั้ง policy ฝั่ง TypeScript และฟังก์ชันฐานข้อมูล
`broadcast_recipient_reason` ให้แยกสถานะ Inbox ออกจากบรอดแคสต์ที่เจ้าของร้านยืนยัน
ยังตรวจ `agent_opted_out` (รวมถึงไม่อนุญาตเมื่อข้อมูลนี้หาย), หลักฐานข้อความขาเข้า
ที่ตรวจสอบแล้วของเพจ/ร้านเดียวกัน, อายุไม่ถึง 24 ชั่วโมง, สิทธิ์ผู้ส่ง/เพจ,
กลุ่มลูกค้า, เครดิต และสวิตช์หยุดฉุกเฉินตามเดิม
ไม่ใช้ `last_message_at` แทนหลักฐาน และไม่สร้างเวลาใหม่ให้ข้อความเก่า

## อัปเดตฐานข้อมูลที่ติดตั้งแล้ว

ทดสอบบน staging ก่อน แล้วรัน `supabase/broadcast-recipient-eligibility.sql`
ในฐานข้อมูลที่ติดตั้ง `broadcast-policy.sql` แล้ว ไฟล์นี้เปลี่ยนเฉพาะฟังก์ชัน
และสิทธิ์เรียกใช้ ไม่แก้ข้อมูลลูกค้า ไม่รีเซ็ต Opt-out และไม่คืนเครดิต/ส่งซ้ำ
สำหรับการติดตั้งใหม่ `broadcast-policy.sql` รวมการแก้นี้แล้ว

หากเคยเริ่มส่งและบันทึกผู้รับเป็น skipped ไว้แล้ว ระบบจะเก็บประวัตินั้นไว้
ไม่เปิดส่งซ้ำอัตโนมัติ ให้ใช้รายการใหม่สำหรับการส่งรอบใหม่และตรวจผู้รับอีกครั้ง

## ข้อความเรื่องความพร้อม

`broadcastReadiness` แยกสาเหตุเป็น ยังไม่เปิดส่ง, รุ่นการตั้งค่าไม่ตรง,
ไม่มีวันที่ตรวจความพร้อมที่ใช้ได้ หรือการตรวจเกิน 30 วัน UI แสดงข้อความตามสาเหตุ
โดยไม่เผยคีย์หรือโทเคน

ตรวจพบว่าใน `.env.local` ยังไม่มีทั้งสี่ค่าต่อไปนี้:

- `BROADCAST_STANDARD_SEND_ENABLED`
- `BROADCAST_POLICY_VERSION`
- `BROADCAST_POLICY_GRAPH_VERSION`
- `BROADCAST_POLICY_REVIEWED_AT`

จึงยังปิดส่งจริงอยู่ ไม่ได้เพิ่มหรือเปิดค่าเหล่านี้ให้โดยอัตโนมัติ
ต้องตรวจนโยบาย/สิทธิ์จริงก่อนตั้งค่าตาม `BROADCAST-2026-10-17.md`
ตัวแปรในระบบ deploy อาจต่างจากไฟล์ในเครื่อง ต้องตรวจแยกกัน

ยังไม่ได้อ่านข้อมูลจริงของลูกค้ารายชื่อที่แจ้ง ไม่ได้รัน SQL บน Supabase จริง
และไม่ได้ส่งข้อความจริง การยืนยันสาเหตุรายบุคคลต้องตรวจข้อมูลของร้านนั้น
หลังอัปเดตฟังก์ชันและกดตรวจสอบผู้รับใหม่

## ค่าเริ่มต้นหน้าสลิป

`/slips` เปิด `banks` เมื่อเปิดระบบรับเงินใหม่ ส่วนระบบเดิมเปิด `settings`
ซึ่งมีการตั้งค่าบัญชีรับเงิน ลิงก์แท็บที่ระบุไว้ชัดเจน เช่น `?tab=history`
ยังคงเปิดประวัติได้ตามเดิม
