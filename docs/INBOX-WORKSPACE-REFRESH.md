# Inbox workspace refresh

ปรับหน้าจอจริงของ `/inbox` ซึ่งใช้ `SmartInboxV2` เป็นหน้าหลักโดยตรงอยู่แล้ว ไม่ใช่แก้เฉพาะป้ายเวอร์ชันหรือ Flag

## การเปลี่ยนแปลงที่เห็นบนหน้าจอ

- ส่วนหัวมีแท็บสถานะอยู่ติดแบนเนอร์ส้ม–ชมพู ตามด้วยตัวเลือกช่องทาง ผู้ดูแล สถานะ และปุ่มมอบหมายแชท บนจอกว้างจัดให้อยู่แถวเดียวกันได้
- แถวสถานะ 5 กลุ่ม: ทั้งหมด ยังไม่ได้อ่าน ผลติดตามดาว ชำระเงินแล้ว เสร็จสิ้น พร้อมจำนวนจากแชทที่โหลดแล้ว ไม่อ้างว่าเป็นทั้งฐานข้อมูล
- ผลติดตามดาวรวมแชทที่ผู้ใช้ติดดาวหรือทำเครื่องหมายติดตามผล โดยนับแต่ละแชทครั้งเดียว ส่วนชำระเงินแล้วใช้สลิปที่ตรวจผ่านหรือแอดมินอนุมัติแล้ว ไม่ใช้รายการรอชำระ
- ช่วงโหลดข้อมูลที่ยังไม่ทราบจะแสดงขีดแทนตัวเลข ข้อมูลตัวกรองจำกัดสูงสุด 1,000 รายการและแสดงคำเตือนเมื่อถึงขีดจำกัด การเปลี่ยนดาว ธงติดตาม และสลิปจะเรียกข้อมูลตัวกรองใหม่
- ตัวกรองนี้ไม่ต้องติดตั้ง SQL เพิ่ม หากยังไม่ได้ติดตั้ง `inbox-follow-up-flags.sql` จะแจ้งว่าการติดตามผลยังไม่พร้อมใช้งาน โดยยังใช้ดาวและตัวกรองชำระเงินแล้วได้
- ช่องค้นหาอยู่ในคอลัมน์รายชื่อ ใช้ข้อความตัวอย่าง “ค้นหาชื่อ” และยังใช้การค้นหาเดิมทั้งหมด นำปุ่ม “เลือกหลายแชท” ออกจากส่วนหัวรายชื่อแล้ว การมอบหมายหลายรายการยังเปิดได้จากปุ่ม “มอบหมายแชท” ด้านบน พร้อมปุ่มยกเลิกเมื่อเปิดโหมดนี้
- คอลัมน์รายชื่อปรับตามจอในช่วง 288–352px ด้วย `clamp(18rem,25vw,22rem)` เพื่อให้รายชื่ออ่านง่ายและเส้นแบ่งอยู่ทางขวามากขึ้น ทั้งเมื่อเปิดและปิดแผงรายละเอียด แผงรายละเอียดบนเดสก์ท็อปอยู่ในช่วง 272–304px พื้นที่ข้อความใช้ความกว้างที่เหลือทั้งหมด บนมือถือรายชื่อขยายเต็มจอ และรายละเอียดเป็นแผงเลื่อนกว้างไม่เกิน 352px
- เมนูนำทางหลักย่อเป็นแถบไอคอน 72px เฉพาะ `/inbox` บนจอตั้งแต่ 1024px ขึ้นไป เมื่อชี้เมาส์หรือโฟกัสด้วยคีย์บอร์ด เมนูขยายเป็น 256px ซ้อนทับชั่วคราวโดยพื้นที่แชทไม่เปลี่ยนขนาดหรือโหลดใหม่ เมื่อออกจากเมนูจะย่อกลับ กด Escape เพื่อย่อได้ หน้ารายงานและหน้าอื่นยังใช้เมนูเต็ม
- รายชื่อแชท ช่องค้นหา และแท็บสถานะเริ่มที่ขอบซ้ายเดียวกัน โดยใช้ระยะขอบหน้า 12px ร่วมกัน พื้นที่ข้อความใช้ความกว้างที่เหลือถัดจากแถบไอคอน
- ป้ายชื่อเมนูแบบไอคอนยังอ่านได้ด้วยโปรแกรมอ่านหน้าจอ และมีชื่อเมื่อชี้เมาส์ เมนูมือถือคงรูปแบบเลื่อนเปิด การกักโฟกัส และการปิดด้วย Escape ตามเดิม การเคลื่อนไหวเคารพการตั้งค่าลดภาพเคลื่อนไหวของอุปกรณ์
- แผงข้อมูลลูกค้ายังพับเก็บได้ และใช้ระยะขอบภายในที่กระชับเพื่อให้ฟอร์มกับข้อมูลอ่านง่าย
- ตัดกล่องออเดอร์/ประวัติซ้ำออกจากแท็บข้อมูล ให้เข้าถึงผ่านแท็บออเดอร์/ประวัติที่มีอยู่ การติดตามลูกค้าย้ายไปแท็บประวัติ
- บนมือถือเมื่อเปิดห้องสนทนา ซ่อนแถวเครื่องมือค้นหา/กรองเพื่อเหลือพื้นที่ข้อความและ Composer; กลับรายการแชทแล้วแสดงเครื่องมืออีกครั้ง

## ไฟล์หลัก

`InboxProCenter.tsx` (header/toolbar), `InboxClient.tsx` (state ที่แชร์ header/list), `ChatList.tsx` (ใช้ตัวกรองจาก toolbar), `Inspector.tsx` (ลดข้อมูลซ้ำ), `lib/features/inbox/inbox-list.ts` (filter helper)

การปรับเลย์เอาต์ใช้ API เดิม: state/search/stars/conversations/workspace/messages/media/draft โดยไม่แก้ข้อมูลจริง เปลี่ยนแพ็กเกจ หรือส่งข้อความจริง ส่วนเครื่องหมายติดตามผลเพิ่มตารางและขยาย API workspace ตามรายละเอียดด้านล่าง

## ติดดาวและติดตามผลในส่วนหัวแชท

ส่วนหัวใช้สถานะ “AI ตอบอัตโนมัติเปิดอยู่” / “AI ปิดอยู่” และปุ่มเลือกเปิด–ปิด แทนปุ่มรับแชท ปิดแชท และเมนูจัดการเดิม เลือกปิดเมื่อยังไม่มีผู้ดูแลจะใช้คำสั่ง `claim` เพื่อให้ผู้กดตอบแชทได้ทันที ถ้ามีผู้ดูแลแล้วใช้ `pause` โดยคงการมอบหมายเดิม เลือกเปิดใช้คำสั่ง `bot` เพื่อคืนให้ระบบอัตโนมัติ คำขอยังผ่าน API, การตรวจเวอร์ชัน สิทธิ์ แพ็กเกจ และโหมดความปลอดภัยเดิม ไม่มีการส่งข้อความจากการกดปุ่มนี้

สถานะแสดงจาก `bot_enabled` การมอบหมาย สถานะแชท และ `auto_reply_enabled` ของร้านที่อ่านจากฐานข้อมูล ปุ่มเปิดจะไม่พร้อมเมื่อร้านปิดระบบอัตโนมัติหรือแพ็กเกจไม่รองรับ AI ผู้ที่ไม่มีสิทธิ์จัดการแชทของผู้ดูแลคนอื่นจะเปลี่ยนสถานะไม่ได้ ฟีเจอร์นี้ใช้ RPC เดิม ไม่ต้องติดตั้ง SQL เพิ่มจากการเปลี่ยนส่วนหัวครั้งนี้

ปุ่มติดดาวใช้ข้อมูลส่วนตัวเดิมใน `inbox_stars` ปุ่มธง “ติดตามผล” ใช้ `inbox_follow_up_flags` แยกตามลูกค้าและผู้ใช้ สถานะทั้งสองเป็นอิสระจากกัน เป็นเครื่องหมายระดับบทสนทนา ไม่ใช่ระดับข้อความ และไม่สร้างคิวติดตามอัตโนมัติหรือส่งข้อความออก

ก่อนใช้งานฟีเจอร์ธง ให้รัน `supabase/inbox-follow-up-flags.sql` หลัง `smart-inbox-v2.sql` ในฐานข้อมูลที่ใช้งานจริง ไฟล์นี้เพิ่มตารางและ RPC โดยไม่แก้ข้อมูลเก่า ถ้ายังไม่มีตาราง ระบบยังโหลดดาวและโน้ตได้ตามเดิม แต่ปุ่มธงจะยังไม่พร้อมใช้งาน

API ใช้การตรวจสมาชิกและสิทธิ์ `customer_management` เดิม อ่านข้อมูลโดยจำกัดร้าน ลูกค้า และผู้ใช้ RPC ตรวจสิทธิ์ซ้ำ ใช้รหัสคำขอเพื่อรองรับการลองใหม่ และใช้เพดาน 30 รายการต่อนาทีร่วมกับการติดดาว/บันทึกโน้ต ปุ่มใช้ `aria-pressed` แสดงสีตามสถานะ ป้องกันการกดซ้ำระหว่างบันทึก และคงสถานะเดิมพร้อมข้อความแจ้งเมื่อบันทึกไม่สำเร็จ

การตรวจ: `node --test scripts/test-inbox-markers.cjs scripts/test-smart-inbox-v2.cjs` ตรวจฐานข้อมูลจำลองและ API ส่วน `node scripts/check-smart-inbox-browser.cjs` ตรวจคอมโพเนนต์จริงใน Chrome รวมการสลับดาว/ธง การกลับเข้าห้องแชท การกดซ้ำ และการบันทึกล้มเหลวแล้วลองใหม่ด้วยรหัสคำขอเดิม การตรวจทั้งหมดใช้ข้อมูลจำลอง ไม่ได้ติดตั้ง SQL ในฐานข้อมูลจริง

ตัวเลือกทุกช่องทาง/Facebook กรองชุดข้อมูลเดียวกันในปัจจุบัน เพราะมี Facebook transport ที่เชื่อมต่อจริงช่องทางเดียว ไม่แสดงช่องทางอื่นว่าใช้งานได้

## ขอบเขตและข้อจำกัด

ยึดคำสั่งก่อนหน้าของผู้ใช้ให้ Inbox เปิด V2 โดยตรง ไม่เพิ่ม Feature Flag กลับตามข้อความเก่าในเอกสารแนบ Sales Page Flag ยังคงเดิม ไม่มีภาพต้นแบบเพิ่มเติมแนบมาในรอบนี้ จึงปรับตามข้อกำหนดข้อความและธีม SnapBot

AI ร่างคำตอบใช้ backend และ entitlement เดิม AI สรุปแชท/แนะนำสินค้า และการแก้ไขโน้ตภายในยังไม่ได้เพิ่มในรอบปรับหน้าจอนี้ การเชื่อมต่อ Facebook จริงและฐานข้อมูลที่ผู้ใช้กำลังใช้งานยังต้องมี migrations/สิทธิ์เดิมครบถ้วน
