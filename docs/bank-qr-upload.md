# รายการบัญชีธนาคารและ QR ประจำบัญชี

แท็บ `/slips?tab=banks` แสดงรายการบัญชีพร้อมโลโก้ผ่าน `BankAccountsManager` ทั้งขณะเปิดและปิด `QR_PAYMENT_DESIGNER_ENABLED` เลือก “ดู / แก้ไขบัญชี” เพื่อดูข้อมูลเดิมและอัปโหลดรูปผ่าน `BankAccountQrUpload` ไม่มีฟอร์มอัปโหลดใหญ่เหนือรายการหรือเครื่องมือสร้าง/ตกแต่ง QR

ก่อนใช้งานจริง ให้รัน `supabase/bank-qr-upload.sql` หลัง `bank-accounts.sql`, `slip-bank-controls.sql` และ `bank-registry.sql` แล้วรัน **`supabase/bank-qr-per-account.sql`** ต่อ หากติดตั้งไฟล์แรกแล้ว ให้รันเฉพาะไฟล์ใหม่ ไฟล์ใหม่เปลี่ยน primary key ของ `bank_receiving_qr` เป็น `(tenant_id, account_id)` โดยรักษารูปและ version เดิม สามารถรันไฟล์ใหม่ซ้ำได้โดยไม่ลบข้อมูล

เพิ่มหรือแก้ไขบัญชีด้วยฟอร์มเดิมก่อน จากนั้นเลือก PNG/JPG ไม่เกิน 5 เมกะไบต์ หรือลากรูปมาวางในบัญชีนั้น แล้วกด “บันทึกการอัปเดตรูป QR Code” เซิร์ฟเวอร์ตรวจชนิดไฟล์จริง ขนาด ความละเอียด และข้อมูล Thai QR/รหัสตรวจสอบ ไม่รับ QR ที่เป็นลิงก์เว็บไซต์ การบันทึกรูปไม่เปลี่ยนธนาคาร เลขบัญชี ชื่อบัญชี สถานะเปิด/ปิด หรือบัญชีหลัก

`GET/POST /api/bank-accounts/qr?tenantId=<UUID>&accountId=<UUID>` ต้องระบุบัญชีเสมอและตรวจสิทธิ์เจ้าของร้าน/ผู้ดูแลและแพ็กเกจก่อนเข้าถึงข้อมูล บัญชีต้องอยู่ในร้านนั้น `GET` คืนข้อมูลบัญชีที่เลือกและ version เฉพาะบัญชี ส่วน `&asset=image` อ่านรูปผ่าน API ที่ตรวจสิทธิ์ ไม่เปิด URL สาธารณะ

ฟังก์ชัน `save_bank_account_qr` ตรวจบัญชีและ snapshot ของธนาคาร/เลขบัญชีอีกครั้งภายในธุรกรรม แล้วผูกรูปและ payload QR กับ `account_id` พร้อมประวัติ `qr_upload` การเปลี่ยนรูปของบัญชีหนึ่งไม่เขียนทับอีกบัญชี และไม่เปลี่ยนบัญชีหลักอัตโนมัติ

`processSlip` และ Payment Pro อ่านบัญชีที่เปิดใช้งานจาก `bank_accounts` เพื่อจับคู่ธนาคารและเลขบัญชีผู้รับกับข้อมูลธุรกรรมที่ SlipOK ตรวจแล้ว รูป QR ถูกเก็บเป็นรูปประจำบัญชี ไม่ใช้การเทียบพิกเซลของรูปเพื่อยืนยันการโอน QR พร้อมเพย์อาจไม่มีเลขบัญชีธนาคาร จึงต้องเลือกบัญชีที่ผูกกับ QR ให้ถูกต้อง

ข้อมูลบัญชี ประวัติและรายการรับเงินเดิมไม่ถูกลบ แต่ละบัญชีมีรูปปัจจุบันหนึ่งรูป รูปเก่าของบัญชีนั้นถูกนำออกจาก storage หลังบันทึกรูปใหม่สำเร็จ หากเปลี่ยนธนาคารหรือเลขบัญชี รูปที่ผูกกับข้อมูลเก่าจะไม่ถูกนำมาแสดง ต้องอัปโหลดใหม่ หากเปลี่ยนเพียงชื่อบัญชี รูปเดิมยังใช้ได้

การแก้ไขพร้อมกันตรวจด้วย version และไม่บันทึกทับข้อมูลใหม่ของผู้อื่น หากผลการบันทึกไม่ชัดเจนเพราะเครือข่ายขัดข้อง ให้โหลดข้อมูลล่าสุดก่อนลองใหม่ ระบบไม่ลบรูปที่อาจบันทึกสำเร็จแล้ว

ตรวจสอบแบบออฟไลน์ ไม่เรียก SlipOK หรือส่งข้อความหาลูกค้าจริง:

```powershell
node --test scripts/test-bank-qr-upload.cjs scripts/test-bank-qr-upload-sql.cjs scripts/test-payment-codes.cjs scripts/test-payment-codes-api.cjs scripts/test-slip-single-page.cjs scripts/test-upload-security.cjs
node node_modules/typescript/bin/tsc --noEmit --allowImportingTsExtensions --incremental false
npm.cmd run build
node scripts/check-qr-designer-browser.cjs
```

ชื่อ browser script เดิมคงไว้ แต่ตรวจหน้ารายการและการแก้ไขบัญชีจริงใน Chrome/Strict Mode: บัญชีสองธนาคาร รูป/เวอร์ชันแยกกัน เลือกไฟล์ ลากวาง ป้องกันคลิกบันทึกซ้ำ โหลดรูปกลับจากข้อมูลจำลอง และตรวจความกว้าง 375/768/1440 พิกเซล
