# รายการบัญชีธนาคารและ QR ประจำบัญชี

แท็บ `/slips?tab=banks` แสดงรายการบัญชีพร้อมโลโก้ผ่าน `BankAccountsManager` ทั้งขณะเปิดและปิด `QR_PAYMENT_DESIGNER_ENABLED` ปุ่มเพิ่มและดู/แก้ไขเปิด `BankAccountForm` ขนาดไม่เกิน `max-w-2xl` ซ้ายเป็นข้อมูลบัญชี ขวาเป็นรูป QR ขนาดเล็ก บนมือถือเรียงลงมา แนบรูปได้ตั้งแต่เพิ่มบัญชีและกด “บันทึกข้อมูลและ QR” ครั้งเดียว

ก่อนใช้งานจริง ให้รัน `supabase/bank-qr-upload.sql` หลัง `bank-accounts.sql`, `slip-bank-controls.sql` และ `bank-registry.sql` แล้วรัน `supabase/bank-qr-per-account.sql` และ **`supabase/bank-account-combined-save.sql`** ตามลำดับ หากติดตั้งสองไฟล์แรกแล้ว ให้รันเฉพาะไฟล์ล่าสุด migrations รักษาข้อมูลบัญชี รูป และ version เดิม และรันซ้ำได้

เลือกธนาคาร กรอกชื่อและเลขที่บัญชี แล้วแนบ PNG/JPG ไม่เกิน 5 เมกะไบต์หรือลากรูปมาวางได้ทันที `BankAccountQrUpload` ทำเฉพาะเลือกรูปและพรีวิว ไม่ยิง API หรือมีปุ่มบันทึกแยก เซิร์ฟเวอร์ตรวจชนิดไฟล์ ขนาด ความละเอียด และข้อมูล Thai QR/รหัสตรวจสอบ ไม่รับ QR ที่เป็นลิงก์เว็บไซต์ หากไม่แนบรูปใหม่ ระบบคงรูปเดิม แต่ถ้าเปลี่ยนธนาคารหรือเลขบัญชีที่มี QR อยู่แล้วต้องแนบรูปใหม่

`POST /api/bank-accounts/save?tenantId=<UUID>` รับ multipart ทั้งบัญชีและรูปในคำขอเดียว อัปโหลดรูปแบบส่วนตัว แล้วเรียก `save_bank_account_with_qr` เพื่อเพิ่ม/แก้ไขข้อมูลและผูก QR ภายในธุรกรรมเดียว หากฐานข้อมูลปฏิเสธจะไม่เหลือบัญชีที่บันทึกเพียงครึ่งเดียว และลบรูปใหม่เฉพาะเมื่อยืนยันได้ว่าธุรกรรมไม่สำเร็จ

`bank_account_save_requests` เก็บผลตาม `requestId` และ fingerprint ที่ server คำนวณจากข้อมูลและไฟล์จริง จึงกดส่งซ้ำหลังเครือข่ายขัดข้องได้โดยไม่เพิ่มบัญชีหรือบันทึก QR ซ้ำ การแก้ไขตรวจ snapshot บัญชีเดิมและ QR version ป้องกันเขียนทับการเปลี่ยนแปลงของแอดมินคนอื่น

`GET/POST /api/bank-accounts/qr?tenantId=<UUID>&accountId=<UUID>` ต้องระบุบัญชีเสมอและตรวจสิทธิ์เจ้าของร้าน/ผู้ดูแลและแพ็กเกจก่อนเข้าถึงข้อมูล บัญชีต้องอยู่ในร้านนั้น `GET` คืนข้อมูลบัญชีที่เลือกและ version เฉพาะบัญชี ส่วน `&asset=image` อ่านรูปผ่าน API ที่ตรวจสิทธิ์ ไม่เปิด URL สาธารณะ

ฟังก์ชัน `save_bank_account_qr` ตรวจบัญชีและ snapshot ของธนาคาร/เลขบัญชีอีกครั้งภายในธุรกรรม แล้วผูกรูปและ payload QR กับ `account_id` พร้อมประวัติ `qr_upload` การเปลี่ยนรูปของบัญชีหนึ่งไม่เขียนทับอีกบัญชี และไม่เปลี่ยนบัญชีหลักอัตโนมัติ

`processSlip` และ Payment Pro อ่านบัญชีที่เปิดใช้งานจาก `bank_accounts` เพื่อจับคู่ธนาคารและเลขบัญชีผู้รับกับข้อมูลธุรกรรมที่ SlipOK ตรวจแล้ว รูป QR ถูกเก็บเป็นรูปประจำบัญชี ไม่ใช้การเทียบพิกเซลของรูปเพื่อยืนยันการโอน QR พร้อมเพย์อาจไม่มีเลขบัญชีธนาคาร จึงต้องเลือกบัญชีที่ผูกกับ QR ให้ถูกต้อง

ข้อมูลบัญชี ประวัติและรายการรับเงินเดิมไม่ถูกลบ แต่ละบัญชีมีรูปปัจจุบันหนึ่งรูป รูปเก่าของบัญชีนั้นถูกนำออกจาก storage หลังบันทึกรูปใหม่สำเร็จ หากเปลี่ยนธนาคารหรือเลขบัญชี รูปที่ผูกกับข้อมูลเก่าจะไม่ถูกนำมาแสดง ต้องอัปโหลดใหม่ หากเปลี่ยนเพียงชื่อบัญชี รูปเดิมยังใช้ได้

การแก้ไขพร้อมกันตรวจด้วย version และไม่บันทึกทับข้อมูลใหม่ของผู้อื่น หากผลการบันทึกไม่ชัดเจนเพราะเครือข่ายขัดข้อง ให้โหลดข้อมูลล่าสุดก่อนลองใหม่ ระบบไม่ลบรูปที่อาจบันทึกสำเร็จแล้ว

ตรวจสอบแบบออฟไลน์ ไม่เรียก SlipOK หรือส่งข้อความหาลูกค้าจริง:

```powershell
node --test scripts/test-bank-qr-upload.cjs scripts/test-bank-qr-upload-sql.cjs scripts/test-payment-codes.cjs scripts/test-payment-codes-api.cjs scripts/test-slip-single-page.cjs scripts/test-upload-security.cjs
node node_modules/typescript/bin/tsc --noEmit --allowImportingTsExtensions --incremental false
npm.cmd run build
node scripts/check-qr-designer-browser.cjs
```

ชื่อ browser script เดิมคงไว้ แต่ตรวจฟอร์มรวมใน Chrome/Strict Mode: สร้างบัญชีใหม่พร้อมรูปได้ก่อนบันทึกใดๆ แก้ไขบัญชีสองธนาคารโดยรูปแยกกัน ป้องกันคลิกซ้ำ โหลดรูปกลับจากข้อมูลจำลอง ลากวาง และตรวจความกว้าง 375/768/1440 พิกเซล รวมถึงความกว้างฟอร์มไม่เกิน 672 พิกเซล
