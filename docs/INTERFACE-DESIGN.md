# ธีม SnapBot จาก Git

## แบนเนอร์หัวข้อหน้าแดชบอร์ด

ตามคำขอปรับหัวข้อให้ตรงกันทุกหน้า ใช้ `components/ui/page-banner.tsx` เป็นแหล่งกำหนดสีร่วม: `bg-gradient-to-r from-orange-500 via-orange-600 to-rose-400` หัวข้อและคำอธิบายเป็นสีขาว ปุ่มที่มีสีข้อความเข้มอยู่บนพื้นขาว แบนเนอร์ยืดหยุ่นและขึ้นบรรทัดใหม่ได้บนมือถือ โดยไม่ปรับพื้นหลังหลักหรือโครงตารางและฟอร์ม

`PageHeader` ใน `components/ui/card.tsx` ใช้แบนเนอร์นี้โดยอัตโนมัติ ครอบคลุมหน้าลูกค้า ติดตามลูกค้า แพ็กเกจ ตั้งค่า รายงาน และหน้าผู้ดูแลระบบ ส่วนหัวเฉพาะของภาพรวม คอมเมนต์ บรอดแคสต์ ร้านค้า ระบบสลิป ศูนย์ AI และกล่องข้อความใช้ `PageBanner` เดียวกัน หน้ารวมแชทใช้ระยะห่างขนาดเล็กเพื่อรักษาพื้นที่อ่านข้อความ

หัวข้อของส่วนที่ฝังในหน้าอื่นใช้ `PageHeader variant="section"` เพื่อแสดงหัวข้อระดับสองแทนการสร้างแบนเนอร์ซ้ำ เมนูที่เปลี่ยนเส้นทางยังไปหน้าปลายทางเดิม หน้าเข้าสู่ระบบและหน้าร้านสาธารณะคงรูปแบบเดิม

รายละเอียดการคืนธีมก่อนการปรับแบนเนอร์รอบนี้อยู่ด้านล่าง

การตรวจรอบแบนเนอร์: ตรวจเส้นทางแดชบอร์ด 20 หน้า พบ 17 หน้าที่มีเนื้อหาและใช้หัวข้อร่วม อีก 3 หน้าเปลี่ยนเส้นทางไปหน้าปลายทางเดิม การ build, TypeScript และตรวจโครงสร้าง import ผ่าน ตรวจ Chrome ด้วยข้อมูลจำลองสำหรับภาพรวม ศูนย์ AI รวมแชท ร้านค้า ติดตามลูกค้า และบรอดแคสต์ที่ความกว้าง 375/768/1440 พิกเซล รวมถึงภาพรวมที่ 1920 พิกเซล ไม่พบเนื้อหาล้นจอในกรณีที่ทดสอบ การตรวจนี้ไม่ได้เรียก API ภายนอกหรือเปลี่ยนข้อมูลจริง

ต้นฉบับที่ผู้ใช้ยืนยันคือ commit `8a0c8ed` — `feat: restore full project snapshot snapbot slip and dashboard` วันที่ 17 ตุลาคม 2026 ไม่ใช่ commit แรกสุด `390d813` ซึ่งยังเป็น LiveCommerce โทนขาว–เขียว

## สีต้นฉบับ

- Sidebar: `bg-linear-to-b from-orange-500 via-orange-500 to-pink-500 text-white`
- เมนูที่เลือก: `bg-white font-medium text-orange-600 shadow-sm` เมนูทั่วไปใช้ข้อความขาวและพื้นขาวโปร่งเมื่อชี้เมาส์
- แบนเนอร์ศูนย์ควบคุม AI: `bg-gradient-to-r from-orange-500 to-pink-500 text-white`
- แถบนำทางมือถือ: `bg-linear-to-r from-orange-500 to-pink-500 text-white`
- หน้าภาพรวม: หัวข้อไม่มีพื้นไล่สี ตามต้นฉบับ ใช้พื้นหน้าภาพรวม `#fffaf8` และการ์ดขาว
- ปุ่มพื้นฐานใช้ emerald-600 ตามไฟล์ `components/ui/button.tsx` ใน commit นี้ ส่วนปุ่มเฉพาะฟีเจอร์ใช้ orange-500 ตามโค้ดเดิม ไม่บังคับให้ทุกปุ่มเป็นสีเดียวกัน

Tailwind รุ่นนี้กำหนดธีมผ่าน `@theme` ใน `app/globals.css` ไม่มีไฟล์ tailwind.config แยก ได้คืนส่วนกำหนดธีมจาก Git และนำตัวแปรสี พื้นผิว เงา และคลาสทดลอง เช่น surface-hero, surface-panel, button-brand, input-polished และ brand-signature ออกจากโค้ดใช้งานแล้ว

## ขอบเขตการคืนค่า

คืนเฉพาะคลาสและค่ารูปแบบ ไม่ใช้ git reset, git revert ทั้ง commit หรือทับไฟล์ทั้งชุด โค้ด API ฐานข้อมูล ระบบสิทธิ์ โควตา การจัดคิว และข้อมูลร้านค้าไม่ถูกเปลี่ยน ชื่อเมนู เนื้อหา ฟีเจอร์ใหม่ และเส้นทางปัจจุบันยังคงอยู่

ใช้สไตล์จาก Git กับคอมโพเนนต์ที่มีต้นฉบับตรงกัน สำหรับฟีเจอร์ที่ยังไม่มีใน commit นั้น คืนสไตล์ก่อนเริ่มทดลองสีและใช้ชุดสีเดียวกับต้นฉบับ ยังคงการจัดการโฟกัสเมนูมือถือ การกด Escape, inert, ลิงก์ข้ามเนื้อหา โครงพื้นที่ทำงานที่ป้องกันการเลื่อนซ้อน และการรองรับ reduced motion

ตรวจเปรียบเทียบโครงสร้าง TypeScript/JSX ก่อนและหลังโดยตัดเฉพาะค่าคลาสออก คอมโพเนนต์ที่เปลี่ยนทั้งหมด 68 ไฟล์มีโค้ดการทำงานเหมือนเดิม ไม่ได้นำฟังก์ชันเก่าจาก commit อ้างอิงกลับมาทับฟังก์ชันปัจจุบัน

## ตรวจสอบ

`npm run build` และ `npx tsc --noEmit --allowImportingTsExtensions --noUnusedLocals --noUnusedParameters` ตรวจการคอมไพล์และชนิดข้อมูล จากนั้นตรวจการโต้ตอบของคอมโพเนนต์จริงใน Chrome:

`node scripts/check-ui-browser.cjs`
`node scripts/check-agent-overview-browser.cjs`
`node scripts/check-smart-inbox-browser.cjs`
`node scripts/check-commerce-browser.cjs`

ชุดตรวจใช้ข้อมูลและ API จำลองใน scripts/fixtures โดยไม่เรียกบริการ AI ส่งข้อความหาลูกค้า หรือสร้างออเดอร์จริง ภาพหน้าจอล่าสุดอยู่ใน `.tmp/ui-preview/` และไม่รวมใน Git การทดสอบเหล่านี้เป็นหลักฐานสำหรับกรณีที่ครอบคลุม ไม่ใช่การรับประกันว่าทุกกรณีในระบบผ่านการทดสอบทั้งหมด

ผลตรวจหลังคืนธีม: build และ TypeScript ผ่าน ชุดทดสอบเฉพาะส่วนผ่าน 216 รายการ การตรวจใน Chrome ทั้ง 4 ชุดผ่าน ไม่พบข้อผิดพลาดในเบราว์เซอร์จากกรณีที่ทดสอบ เส้นทาง 127 ไฟล์และไฟล์ตั้งค่า 7 ไฟล์คงเดิมตามการตรวจเปรียบเทียบ
