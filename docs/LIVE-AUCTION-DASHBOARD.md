# แดชบอร์ดไลฟ์สดการประมูลครบวงจร

เส้นทาง `/live-auction` อยู่ใต้เมนู **ไลฟ์สด CF** ใน Sidebar
ทั้ง 4 ส่วนเรียงในหน้าเดียว: ข้อมูลไลฟ์และสรุปบัญชี → เปิดรอบและตั้งคำดัก → ลูกค้า/บิล/สลิป → จัดส่ง
หน้า CF และ Console แบบแท็บเดิมยังใช้ได้ตามปกติ

## ติดตั้ง

ฐานข้อมูลเดิมที่ติดตั้ง Shipping และชนิดรายการแล้ว ให้รัน
`supabase/live-auction-dashboard.sql` หลัง `shipping-fulfillment.sql` และ `live-order-types.sql`
แล้วรัน `supabase/live-auction-instant-winners.sql` สำหรับข้อมูลผู้โอน ตัวเลขจำนวนคนที่ตรงบิด และ Template ยอดรวมสะสม
แล้วรัน `supabase/live-auction-customer-workspace.sql` สำหรับการรวมรายชื่อ ฟิลเตอร์ผลจับบิด และหมายเหตุต่อ Session
แล้วรัน `supabase/live-auction-thai-workflow.sql` สำหรับคำปิดรอบที่กำหนดเอง การรับบิดแบบเงียบ และข้อมูลรอบที่กำลังเปิด
แล้วรัน `supabase/live-auction-customer-columns.sql` เพื่อแสดงข้อความคอมเมนต์ล่าสุดในตารางลูกค้าแบบ 7 คอลัมน์
จากนั้น deploy แอป รุ่นใหม่รวม migration นี้ใน `complete_schema.sql` และ `full_database_setup.sql` แล้ว
งานนี้ยังไม่ได้รัน migration หรือ deploy บน production

ต้องมีเพจที่เชื่อมต่อและบัญชีรับเงินของร้านก่อนเริ่ม Session
การส่งบิล Messenger ต้องตั้งค่า `LIVE_CF_APP_URL` และ `LIVE_CF_PAYMENT_LINK_SECRET`
การเริ่ม Session ยังไม่ส่งข้อความหรือเปิดรายการประมูล ส่วนการเปิดรอบจะตรวจความพร้อมของลิงก์ชำระเงินอีกครั้ง

## การใช้งานและขอบเขตข้อมูล

- เลือกเพจ/ไลฟ์ แล้วกดเริ่ม Session การเลือกไลฟ์เดิมจะเปิด Session เดิมและคงค่าตั้งค่า/บิลไว้
- Session ที่จบแล้วดูย้อนหลังได้ แต่เริ่มใหม่ด้วยวิดีโอเดิมหรือแก้ Automation ไม่ได้
- ตัวเลือก Session กลางควบคุมรอบประมูล ลูกค้า สลิป และจัดส่งพร้อมกัน
- จำนวนเงินจาก ledger เดิมและ SQL numeric; กำไรใช้ยอดโอนที่ตรวจผ่านลบต้นทุน ค่าแอด และค่าส่งที่ร้านจ่าย
- ค่าส่งในกล่องการเงินเป็นค่าใช้จ่ายร้าน แยกจากค่าส่งที่เรียกเก็บในบิล
- คำดักเริ่มต้น `1` และคำปิดเริ่มต้น `ปิด, x` แก้ได้ตามต้องการ คั่นคำด้วยจุลภาค คำดักและคำปิดห้ามซ้ำกัน
- คำดักเพิ่มราคาหนึ่งครั้ง ส่วนตัวเลขราคาชัดเจนใช้เสนอราคาได้โดยตรง ไม่มีปุ่มนับ กระดานราคา ประวัติเคาะ หรือปุ่มคำสำเร็จรูปในหน้านี้
- ผู้ขายนับปากเปล่าและพิมพ์คำปิดในนามเพจหรือผู้ช่วยที่มีสิทธิ์ ฐานข้อมูลตรวจคำปิดจากคอมเมนต์จริงอีกครั้งภายใต้การล็อกรอบ
- ค่าตั้งค่าใช้กับรอบปัจจุบันและรอบใหม่ บัญชีที่เลือกในฟอร์มใช้กับรอบนั้น บิลสะสมที่เปิดแล้วคงบัญชีเดิมเพื่อให้ตรวจยอดโอนถูกต้อง
- `order_type = auction` และการรวม CF/ประมูลใน Customer Tab เดียวต่อไลฟ์ ใช้ ledger เดิม คิดค่าส่งครั้งเดียว
- ส่วนที่ 2 แยกข้อความสองแบบพร้อมสวิตช์อิสระ ข้อความสาธารณะส่งใต้คอมเมนต์ของผู้ชนะเท่านั้น ระหว่างรับบิดจะบันทึกเงียบ ๆ ตัวแปรที่ผู้ขายเห็นเป็นภาษาไทย เช่น `{ชื่อลูกค้า}` และ `{ยอดรวมสะสม}`
- ใน Session Automation `{total}` คือยอดรวมบิลสะสม ส่วน `{remaining}` คือยอดค้างสุทธิ และ `{bank_account}` คือบัญชีของบิล
- เมื่อเปิด Messenger ระบบส่งทันทีต่อรายการที่ปิดชนะ โดยอ่าน Customer Tab ใหม่ทุกครั้ง ไม่มีการตั้งเวลา หน่วง หรือรวมหลายชัยชนะรอส่ง
- ส่งบิลผู้ชนะก่อนข้อความประกาศสาธารณะ ใช้ outbox ต่อรอบป้องกันการส่งซ้ำจาก webhook replay และไม่ลองส่งซ้ำเมื่อผลจากผู้ให้บริการไม่แน่ชัด
- การประมูลแบบเดิมนอก Session Automation ยังคงความหมาย `{total}` เป็นยอดค้างสุทธิตาม Template เดิม
- ตารางลูกค้าและสลิปเรียงคู่กันบน Desktop และวางต่อกันบนจอแคบ สลิปแสดงชื่อผู้โอนและธนาคารจาก SlipOK แยกจากชื่อ Facebook
- ส่วนที่ 3 ใช้ Grid 12 ช่อง: ลูกค้า 7 ช่อง และสลิป 5 ช่อง รายชื่อลูกค้ารวมคนคอมเมนต์กับบิลเป็นตารางเดียวตามรหัส Facebook/ลูกค้า ไม่รวมจากชื่อที่อาจซ้ำกัน
- เลือกทั้งหมดเลือกเฉพาะแถวที่แสดง ฟิลเตอร์ "เฉพาะคนตรงคำดัก" ใช้หลักฐานบิด/CF ใน Session และล้างการเลือกเมื่อเปลี่ยนฟิลเตอร์
- "ดึงข้อมูลคนที่เลือก" นำชื่อจากคอมเมนต์และบิลที่มีอยู่มาผูกโปรไฟล์ใน Inbox แล้วโหลดข้อมูลล่าสุด ไม่มีการเรียก Meta หรือสร้างสิทธิ์หน้าต่าง Messenger จำลอง
- ตารางลูกค้ามี 7 คอลัมน์: เลือก ชื่อ ยอดซื้อ สถานะโอน คอมเมนต์ล่าสุด แชท และเวลา (ชั่วโมง:นาที:วินาที ตามเวลาไทย) จำนวนรายการชนะอยู่ใต้ยอดซื้อ คลิกยอดเพื่อเปิดหน้าตรวจที่มาและปรับยอดเดิม
- ข้อความล่าสุดอ่านจากคอมเมนต์ของเพจและไลฟ์ที่เลือกเท่านั้น ลูกค้าที่มีบิลแต่ไม่มีคอมเมนต์ในไลฟ์นี้แสดงขีดแทนข้อความและเวลา
- ตารางสลิปแบ่งหน้าจาก snapshot (สูงสุด 500 สลิปล่าสุด) เริ่ม 10 แถว เลือก 20/50 ได้ และรีเซ็ตเมื่อเปลี่ยน Session
- แถบสถานะนับต่อบิล: โอนแล้ว = มีเงินรับแล้ว, ยังไม่โอน = ค้างและยังไม่รับเงิน, ครบ = ยอดพอดี, ขาด = ยังมีคงเหลือ, เกิน = มีเครดิต (ผู้โอนบางส่วนจึงอยู่ทั้งกลุ่มโอนแล้วและขาด)
- ตรงคำดักนับผู้บิด/CF ที่ตรงใน Session แบบไม่ซ้ำ ไม่ใช้จำนวนคอมเมนต์แทนจำนวนคน
- รายชื่อคนคอมเมนต์และสลิปแสดงล่าสุดสูงสุด 500 รายการ พร้อมแจ้งจำนวนเมื่อเกินขีดจำกัด ตัวเลขสรุปและบิลไม่ถูกตัดตามรายการที่แสดง
- การดูรูปสลิปใช้ API ตรวจสิทธิ์และ signed URL เดิม ไม่มีการเผยแพร่ไฟล์สลิปเป็น public
- ทวงยอดใช้คิวเดิมที่เว้นอย่างน้อย 5 วินาทีต่อคนต่อเพจ (12 คน/นาที) และตรวจยอด/สิทธิ์ส่งซ้ำก่อนส่งจริง
- จัดส่งแสดงเฉพาะบิลที่ชำระครบใน Session นั้น ใช้ที่อยู่จาก Messenger ซึ่งต้องยืนยันก่อนพิมพ์
- พิมพ์ฉลาก 100×150 mm, A4 สี่รายการ และ CSV ใช้ API เดิมที่ตรวจบิลและที่อยู่ล่าสุด
- Bee Move เป็น UI เตรียมไฟล์และช่อง API Key ในอนาคตซึ่งยังปิดไว้ ไม่มีการบันทึกคีย์หรือจองขนส่งจริง

## การป้องกันข้อมูลซ้ำ/ข้าม Session

API ใหม่ `/api/live-auction/session` ตรวจ owner และ same-origin ก่อนอ่านหรือเขียน
RPC ตรวจ tenant/page/bank และใช้ request ID ที่ผูกกับ payload/actor เพื่อรองรับ retry
การแก้ Automation ใช้ revision แยกจากบัญชีการเงิน และ lock รอบประมูลก่อน Session เช่นเดียวกับการปิดรอบ
ตารางจัดส่งถูกกรองทั้งจาก API และใน UI โดยล็อกตัวเลือก Session ขณะฝังในแดชบอร์ด
เมื่อสลับ Session จะล้าง snapshot/selection/modal และยกเลิกคำขอเก่า

## ตรวจสอบ

- `npm run test:live-auction-dashboard`: API boundary, parser switches, SQL start/replay/revision, สลิป/บิล/ขนส่งแยก Session
- `npm run test:live-auction-dashboard:ui`: Chromium ทดสอบส่วน 1–4, คำดัก/คำปิด, ข้อความภาษาไทย, เปิด/ยกเลิกรอบ, พิมพ์/CSV, สลับ Session, ที่มาของยอด/ตามยอด และจอ 375/768/1024/1440px
- `npm run test:schema`: ติดตั้งใหม่ อัปเกรด และรัน migration ซ้ำ

ชุดทดสอบใช้ API จำลองและ PGlite ไม่เรียก Meta, SlipOK หรือผู้ให้บริการขนส่งจริง
