# ตรวจสลิปอัตโนมัติเฉพาะออเดอร์ค้างชำระ และเงียบเมื่อไม่ผ่าน

Facebook webhook ตรวจ `orders` ผ่าน `pendingOrders(db, customer.id, tenant.id)` โดยกรอง `customer_id`, `tenant_id` และ `status = pending_payment` ก่อนเลือกเส้นทางตรวจสลิป ต้องมีรายการจริงและยอดรวมเป็นจำนวนบวก ไม่ใช้เพียงสถานะแชทหรือการเปิดสวิตช์ Auto-Pilot

เมื่อไม่มีออเดอร์ค้างชำระ รูปจะไม่ถูกดาวน์โหลดเพื่อส่ง SlipOK และไม่ใช้เครดิตตรวจสลิป แต่ยังเข้าเส้นทางรูปสินค้า/รูปทั่วไปของ Vision หรือ AI ตามการตั้งค่าเดิมได้ ไม่ปิดบอททั่วไปทั้งระบบ

บันทึกการเลือกเส้นทางไว้ใน checkpoint `slip-route` เพื่อไม่ให้ webhook ที่กลับมาทำต่อหลังจ่ายเงินแล้วเปลี่ยนรูปเดิมไปเป็นงาน Vision โดยไม่ตั้งใจ ก่อนตรวจแต่ละรูปจะอ่าน pending orders ใหม่อีกครั้ง จึงข้ามรูปถัดไปในอัลบั้มหากรูปแรกชำระออเดอร์หมดแล้ว การ replay ไม่ตรวจหรือส่งซ้ำ

หากมีออเดอร์ค้างและส่งรูปทั่วไป ระบบอาจลองตรวจรูปนั้น แต่ผลไม่ผ่าน/อ่านไม่ได้จะไม่ตอบข้อความผิดพลาดกลับลูกค้า `notifySlipResult` ส่งเฉพาะ `valid` เท่านั้น ทั้ง error, fake, duplicate, wrong_receiver และ amount_mismatch อยู่ในโหมดเงียบ ผลที่ตรวจแล้วและรายละเอียดปัญหายังคงอยู่ให้แอดมินดูในแดชบอร์ด ไม่เปลี่ยนผลไม่ผ่านให้เป็นชำระสำเร็จ

สลิปที่ผ่านยังส่งข้อความยืนยันตาม template ของร้านไปยัง sender PSID แม้แอดมินรับช่วงอยู่ โดยรักษาการตรวจบัญชี ยอดโอน อ้างอิง สลิปซ้ำ โควตา การปิดระบบ และ Messenger window ตามเดิม ข้อความ AI ทั่วไปยังหยุดระหว่างแอดมินรับช่วง

หากอ่านออเดอร์ไม่ได้ จะไม่เดาว่ามี pending และไม่เรียกผู้ตรวจสลิป งาน webhook ใช้กลไก retry/error เดิมโดยไม่ยิงข้อความล้มเหลวหาลูกค้า

ข้อกำหนดนี้ใช้กับการตรวจอัตโนมัติจากแชท การกดตรวจโดยแอดมินและการตรวจสลิปชำระแพ็กเกจยังทำงานตามเดิม รายการ pending ต้องเป็น `orders` ที่ผูกกับลูกค้าแชทในร้านนั้น ไม่จับคู่ `commerce_customers`/ออเดอร์หน้าร้านจากชื่อหรือเบอร์โทรโดยการคาดเดา
