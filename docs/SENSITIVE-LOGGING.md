# การป้องกันข้อมูลลับในบันทึก Facebook และตรวจสลิป

ขอบเขตครั้งนี้คือ `lib/integrations/facebook/client.ts` และ `app/api/payments/verify-slip/route.ts` พร้อมเครื่องมือส่วนกลาง `lib/safe-logging.ts` ไม่ต้องติดตั้ง SQL หรือเปลี่ยนค่าแวดล้อม

## ข้อมูลที่บันทึกได้

`logSafeEvent` รับข้อมูลผ่านชนิด `SafeLogMetadata` และตรวจซ้ำก่อนส่งออกเป็น JSON หนึ่งบรรทัด โดยสร้างวัตถุใหม่จากรายการฟิลด์ที่อนุญาตเท่านั้น ไม่ส่งต่อวัตถุต้นฉบับให้ console

- `requestId`: UUID สุ่มที่เซิร์ฟเวอร์สร้างเอง ไม่ใช้ค่าจาก request header
- `eventType`: ประเภทเหตุการณ์จากรายการที่กำหนดไว้ในโค้ด
- `status`: สถานะจากรายการที่กำหนด หรือ HTTP status 100–599
- `durationMs`: จำนวนเต็มไม่ติดลบและมีขอบเขต
- `errorCode`: หมวดหมู่แบบปิดบัง เช่น `AUTH_***`, `DB_CONFLICT_***`, `UNKNOWN_***` ไม่คงข้อความหรือรหัสที่ผู้ให้บริการส่งมาแบบอิสระ

ฟิลด์ส่วนเกิน รวมถึงวัตถุซ้อน วงอ้างอิงวน `toJSON`, profile, request, response, token, account และ Error object จะไม่ถูกส่งเข้า serializer ค่าของฟิลด์ที่อนุญาตแต่ไม่ผ่านการตรวจจะถูกแทนด้วยค่าปลอดภัย หากระบบบันทึกขัดข้องจะไม่ยกเลิกการส่งข้อความหรือกระตุ้นการชำระเงินซ้ำ

## สิ่งที่เปลี่ยน

- ลบการพิมพ์โปรไฟล์ ชื่อผู้ติดต่อ รหัสผู้ส่ง รูปภาพ URL ผลตรวจสลิปเต็ม ยอดเงิน หมายเลขรายการ ร้านค้า และยอดเครดิตออกจาก log ในสองไฟล์เป้าหมาย
- Facebook debug mode ใช้เครื่องมือเดียวกัน ไม่มีสิทธิ์เปิดเผยรายละเอียดเพิ่มเติม
- `SendApiError` ไม่เก็บ response body ในข้อความหรือพร็อพเพอร์ตีอีกต่อไป ยังคง `status`, `code`, `subcode` สำหรับตรรกะตรวจช่วงเวลาส่งและการจัดการ retry เดิม ส่วนที่เขียนลง log จะผ่านการปิดบังรหัสเสมอ
- ความผิดพลาดเครือข่ายและ JSON ของการส่ง Facebook ถูกแทนด้วยข้อความคงที่ โดยไม่แนบ `cause` หรือข้อความเดิมที่อาจมี credential/URL
- ข้อความผิดพลาดจาก Graph ที่คืนให้หน้าตั้งค่าจะไม่แนบข้อความผิดพลาดดิบจากผู้ให้บริการ
- เส้นทางตรวจสลิปครอบคลุมข้อผิดพลาดตั้งแต่ตรวจผู้ใช้จนถึงอ่าน billing และตอบข้อความทั่วไป โดยไม่บันทึกชื่อคลาส exception ที่ผู้ให้บริการอาจกำหนดเอง
- การตรวจสลิปตอบ `X-Request-ID` และ `Cache-Control: no-store` เพื่อใช้อ้างอิงเหตุการณ์โดยไม่ต้องพิมพ์ข้อมูลการชำระเงิน

ผลตรวจสลิปยังใช้ในหน่วยความจำเพื่อตรวจความถูกต้องและบันทึกหลักฐานตามเดิม ไม่เปลี่ยนตรรกะตรวจผู้รับ จำนวนเงิน สิทธิ์ร้านค้า หรือการยืนยันแพ็กเกจ ตัวเลือก `log: true` ของบริการตรวจสลิปเป็นการตรวจหลักฐาน/สลิปซ้ำของผู้ให้บริการ ไม่ใช่การพิมพ์ผลลง console ของแอป จึงยังคงไว้ตามสัญญาการชำระเงินเดิม

เครื่องมือส่วนกลางไม่รับ Error object หรือ stack เพื่อส่งต่อให้ระบบติดตามข้อผิดพลาด ไม่มีการติดตั้ง SDK ติดตามข้อมูลเพิ่มเติม และไม่ได้เปลี่ยน log ของโมดูลอื่นนอกขอบเขตนี้

## การทดสอบ

รันโดยใช้ credential จำลอง ไม่มีการอ่าน `.env` เรียก Meta/ผู้ให้บริการจริง หรือเปลี่ยนฐานข้อมูลจริง:

```text
node --test scripts/test-sensitive-logging.cjs scripts/test-facebook-page-token.cjs scripts/test-tenant-page-connections.cjs scripts/test-restored-exports.cjs
npm run build
```

ชุดทดสอบ 66 กรณีตรวจทั้งพฤติกรรมเดิมและการไม่เปิดเผยข้อมูลในเส้นทางสำเร็จ ถูกปฏิเสธ เครือข่ายล้มเหลว JSON ผิดรูปแบบ บันทึกหลักฐานไม่สำเร็จ เปิดแพ็กเกจไม่สำเร็จ และ exception จาก auth/provider/billing รวมถึง debug mode, payload ซ้อน/วน, log injection และ console ที่ขัดข้อง
