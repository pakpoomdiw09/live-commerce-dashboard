# กฎของทางร้าน

หน้า `/chatbot/conversations` แท็บ **กฎของทางร้าน** ใช้ตารางจริง 5 คอลัมน์: ลำดับ หัวข้อ/ประเภท รายละเอียดกฎ สถานะ และจัดการ รองรับสูงสุด 200 ข้อ และ 50,000 ตัวอักษรรวมข้อมูลจัดเก็บ หน้าจอเล็กเลื่อนภายในตารางได้

กดเพิ่มกฎเพื่อแทรกแถวใหม่ คลิกช่องรายละเอียดหรือปุ่มแก้ไขแล้วบันทึกในแถว หมวดหมู่และสวิตช์บันทึกทันทีเมื่อไม่ได้แก้ไขข้อความอยู่ หากกำลังแก้ไขแถวอยู่ การเปลี่ยนค่าทั้งแถวจะบันทึกพร้อมปุ่มบันทึก กฎที่ปิดยังคงแก้ไข/ลบได้แต่ไม่เข้าบริบท AI

## ติดตั้ง

รัน `supabase/store-rules.sql` หลัง `automation.sql`, `agent-control.sql` และ `ai-paid-access.sql` ก่อนใช้งานการบันทึกข้อความยาว สคริปต์ขยายข้อจำกัดทั้งตารางและฟังก์ชันบันทึก รักษาประวัติรุ่นกฎเดิม ตรวจเจ้าของร้าน/แพ็กเกจเช่นเดิม และรันซ้ำได้ หากรันไฟล์ฐานเก่าซ้ำ ให้รันไฟล์นี้ตามอีกครั้ง

ไม่มีการเรียก AI การส่งข้อความ การอนุมัติการชำระ หรือการเปลี่ยนโควตาจากสคริปต์นี้ รอบพัฒนาไม่ได้ติดตั้งบนฐานข้อมูลจริง

จากนั้นรัน `supabase/store-rule-items.sql` เพื่อเพิ่มการบันทึกรายการแบบตรวจค่าล่าสุดก่อนเขียน (`save_store_rule_items`) ถ้าอีกหน้าต่างเปลี่ยนข้อมูลระหว่างบันทึกจะตอบข้อขัดแย้งและไม่เขียนทับข้อมูลใหม่ คงการตรวจเจ้าของร้าน แพ็กเกจ และประวัติการเปลี่ยนแปลงเดิมไว้

สำหรับตารางรุ่นใหม่ ให้รัน `store-rule-items.sql` ฉบับล่าสุดซ้ำเพื่อเพิ่มการตรวจหมวดหมู่และสถานะชนิดบูลีนในฐานข้อมูล ฟิลด์ JSON เพิ่ม `category` และ `enabled` โดยไม่เพิ่มตารางหรือเปลี่ยนข้อมูลเดิม กฎเดิมที่ไม่มีสองฟิลด์นี้ถือเป็นหมวดทั่วไปและเปิดใช้งาน

API `/api/agent-control/rules` ใช้ POST/PATCH/DELETE สำหรับแต่ละข้อ โดยบันทึกรายการพร้อมรหัสคงที่เป็น JSON ใน `bot_settings.ai_instructions` ภายในธุรกรรมเดียวกัน การแก้/ลบต้องตรงกับข้อความก่อนแก้ที่อ่านมา การเพิ่มซ้ำด้วยรหัสเดิมและข้อความเดิมไม่สร้างรายการซ้ำ ข้อความรูปแบบเดิมคงเป็นรายการเก่าหนึ่งข้อเพื่อไม่เดาหรือทำลายย่อหน้า และยังแก้ไขต่อได้

ก่อนส่งให้ AI ระบบถอดข้อมูลจัดเก็บและรวมเฉพาะข้อความข้อที่เปิดใช้งาน จึงไม่ส่งรหัสรายการให้โมเดล รายการที่ลบหรือปิดไม่อยู่ในบริบทของคำขอถัดไป ผู้ใช้ต้องยืนยันก่อนลบ หากบันทึกไม่สำเร็จ ข้อความในแถวยังอยู่ให้ลองใหม่ และสวิตช์ยังแสดงค่าที่บันทึกสำเร็จล่าสุด

## การทำงาน

- เก็บกฎใน `bot_settings.ai_instructions` แยกตาม `tenant_id` API ตรวจขีดจำกัด 50,000 ตัวอักษรและข้อมูลลับก่อนเรียก `save_agent_prompt`
- ทุกคำขอ AI อ่านค่าปัจจุบันจากฐานข้อมูล ไม่ตัดเหลือ 8,000 ตัวอักษร และแนบข้อความทั้งหมดในคำสั่งระบบ พร้อมรายการข้อความอ้างอิงที่ AI เลือกมาตอบได้ กฎที่ยาวเกินขีดจำกัดถูกปฏิเสธก่อนหักโควตา
- ใช้กฎตอบคำถามทั่วไป เช่น ค่าส่งและเวลาตัดรอบ รวมถึงใช้รอบส่งเป็นข้อมูลสำหรับคำถามกว้าง ๆ ว่า “ส่งของยัง” แต่ไม่ถือเป็นหลักฐานยืนยันการจัดส่งเฉพาะออเดอร์ การติดตามพัสดุหรือยืนยันสถานะจริงยังต้องมีข้อมูลอ้างอิง
- ข้อความจากฟอร์มจัดหมวดหมู่รุ่นก่อนถูกแปลงกลับเป็นข้อความอ่านได้ในช่องเดียว ข้อมูลที่ยังไม่บันทึกไม่ถูกทับจากการบันทึกตั้งค่าอื่น
- เลิกอ่าน `agent_knowledge_sources` ทั้งหน้าศูนย์ควบคุม เส้นทาง AI และการจำลอง ลบ API จัดการ Q&A จากแอป และปิดสิทธิ์เรียกฟังก์ชันจัดการ Q&A เดิม ข้อมูลเก่าในตารางยังคงอยู่เป็นประวัติและไม่ถูกนำมาใช้ตอบ
- การตั้งค่าคำสำคัญยังแยกทำงานตามเดิม มีลำดับก่อน AI หน้าตั้งค่าคำตอบไม่เขียนกฎของร้านทับค่าจากแท็บหลัก
- สิทธิ์แพ็กเกจ โควตา การรับช่วงของแอดมิน การยินยอมรับข้อความ และการพักระบบฉุกเฉินยังตรวจเหมือนเดิม
