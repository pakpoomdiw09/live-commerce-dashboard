# เพิ่มลูกค้าเข้าคิว Smart Follow-up

**เวอร์ชันล่าสุด:** ติดตั้ง `follow-up-simplified.sql` และ `follow-up-step-settings.sql` ต่อท้าย migration เดิม แล้วใช้ขั้นตอนใน [FOLLOW-UP-SIMPLIFIED.md](FOLLOW-UP-SIMPLIFIED.md) แทนเงื่อนไขนโยบายด้านล่างซึ่งอธิบายเวอร์ชันก่อนหน้า

ก่อน deploy ให้รัน `supabase/manual-follow-ups.sql` ฉบับล่าสุดใน Supabase SQL Editor หลังจากติดตั้ง `smart-follow-ups.sql` และ `smart-follow-up-presend.sql` (ถ้าใช้งาน) แล้ว รันซ้ำได้ ไม่ส่งข้อความจริง หากติดตั้ง Worker migration ใหม่ภายหลัง ให้รันไฟล์ manual นี้ซ้ำเพื่อคงการรองรับรายการไม่มีออเดอร์

ในหน้า Smart Follow-up กด **เพิ่มรายชื่อ** ด้านบนตารางคิว ค้นหาด้วยชื่อ, Customer ID หรือ Facebook PSID แล้วเลือกประเภทและข้อมูลอ้างอิง:

- ค้างชำระ: เลือกออเดอร์ค้างชำระที่ยืนยันแล้ว หรือไม่ระบุออเดอร์
- สนใจสินค้า: เลือกสินค้าเพื่ออ้างอิงข้อความล่าสุด หรือไม่ระบุสินค้าก็เพิ่มเข้าคิวได้ แม้มีออเดอร์หรือยังไม่มีออเดอร์
- หลังการขาย: เลือกออเดอร์ที่มีหลักฐานส่งถึงแล้ว หรือไม่ระบุออเดอร์

ออเดอร์และสินค้าอ้างอิงไม่บังคับทุกประเภท Dropdown แสดงออเดอร์ล่าสุด 50 รายการของลูกค้าในร้านเดียวกัน พร้อม ID ย่อ ยอดและสถานะ ออเดอร์สถานะไม่ตรงประเภทจะแสดงแต่เลือกไม่ได้ สามารถเลือกไม่ระบุแทน เมื่อมี Realtime event ของออเดอร์ลูกค้ารายนั้น จะโหลดใหม่แบบ debounce และถอด subscription เมื่อเปลี่ยนลูกค้าหรือปิด Modal

รายการไม่มีออเดอร์เริ่ม `pending` และนับเวลาจากตอนเพิ่ม ใช้ข้อความติดตามทั่วไปที่ไม่แต่งชื่อสินค้า ยอดเงิน หรือสถานะชำระ/จัดส่ง เมื่อ Worker ประมวลผลจะเปลี่ยนเป็นรอตรวจร่าง แอดมินแก้ข้อความและอนุมัติผ่านปุ่ม **ตรวจร่าง** ก่อนส่งเสมอ แม้ไม่ได้เปิด AI ก็ตาม มีได้หนึ่งชุดงานที่ยังไม่จบต่อคน/ประเภทเพื่อป้องกันการกดซ้ำ

ต้องเปิดนโยบายและ Workflow ประเภทนั้นและมีแพ็กเกจรองรับ ระบบใช้ข้อความและกำหนดเวลาเดิมของ Workflow โดยนับจากเหตุการณ์อ้างอิง หากถึงกำหนดแล้ว Worker จะตรวจในรอบถัดไป รายการใหม่เริ่มเป็น `pending` และตารางรีเฟรชทันทีหลังเพิ่มสำเร็จ การเลือกข้อมูลอ้างอิงเดิมซ้ำไม่สร้างคิวซ้ำ งานที่จบแล้วไม่ถูกเปิดส่งใหม่

การเพิ่มเข้าคิวไม่ใช่การส่งทันที Worker ยังคงตรวจสิทธิ์ การหยุดรับข้อความ การรับช่วงโดยแอดมิน เวลาส่ง โควตา และการอนุมัติ AI ตามเดิม หากเปิดตรวจร่าง AI งานจะเปลี่ยนเป็นรอแอดมินเมื่อ Worker ประมวลผล

ใน **ตรวจร่าง → AI ช่วยร่าง** ระบบดึงประวัติแชทล่าสุด 30 ข้อความ จำกัดข้อความละ 2,000 ตัวอักษรให้ Gemini เลือกหลักฐานยอดตกลงและปัญหาการโอน ตรวจว่า ID และคำอ้างมีอยู่จริงในแชทก่อนประกอบร่าง พร้อมแสดงหลักฐานให้ผู้ดูแลอ่าน ไม่ใช้โหมดเลือกข้อมูลสินค้าของ AI ตอบแชททั่วไปซึ่งไม่รองรับการวิเคราะห์ยอดลูกค้าเฉพาะราย หากยอดขัดแย้ง หลักฐานไม่ชัดหรือผู้ให้บริการผิดพลาด ใช้ข้อความติดตามกลาง ๆ แทน การกล่าวว่าโอนแล้วในแชทไม่ใช่การยืนยันยอดชำระจริง การร่างใช้สิทธิ์และโควตา AI เดิม ไม่แก้ออเดอร์หรือส่ง Messenger โดยตรง

ลิงก์โปรไฟล์ Facebook ไม่ใช่ Messenger PSID จึงต้องเลือกลูกค้าที่มีอยู่ในแชท ไม่สร้างผู้รับที่ส่งข้อความไม่ได้จากลิงก์อย่างเดียว

API: `GET /api/follow-ups/manual?tenantId=...&q=...` ค้นหาสูงสุด 30 คน; เพิ่ม `customerId` เพื่อดูออเดอร์ล่าสุด 50 รายการและสินค้าใช้งาน 200 รายการ `POST` ใช้ `{tenantId, customerId, kind, referenceId}` โดย `referenceId` เป็น `null` หรือไม่ส่งก็ได้สำหรับค้างชำระ/หลังการขาย ตรวจสิทธิ์ร้านทั้งที่ API และ RPC ไม่มี Polling เพิ่มจากฟอร์ม ค้นหาหน่วง 300ms และยกเลิก request เก่า
