# แดชบอร์ดประมูลราย Session

เปิด `/live-cf?mode=auction` แล้วเลือก Session ด้านบน มีสรุปยอดโอนจริง ค่าใช้จ่าย กำไร ผลประมูลแต่ละรอบ และยอดบิลลูกค้า อัปเดตทุก 5 วินาทีขณะเปิดแท็บ สามารถเปิด Session เดิมด้วย `&session=<session UUID>` ได้

## ติดตั้ง

- ฐานข้อมูลเดิม: รัน `supabase/live-session-dashboard.sql` หลัง `supabase/auction-experience.sql` และ `supabase/customer-tabs.sql`
- ฐานข้อมูลใหม่: ใช้ `supabase/complete_schema.sql` ซึ่งรวม migration ใหม่แล้ว ไม่ต้องรัน migration เก่าซ้ำหลัง migration นี้
- Deploy โค้ดพร้อม Worker เวอร์ชันเดียวกัน ใช้ Supabase, Facebook Page, SlipOK, signing secret และ Scheduler เดิมของระบบบิลสะสม ไม่ต้องสร้างบริการส่งข้อความอีกชุด
- Worker เดิม `GET/POST /api/cron/customer-tabs` และ `/api/cron/facebook-webhooks` รองรับข้อความกำหนดเองและคิวใหม่แล้ว หากส่งหลายคนควรตั้ง Scheduler ทุกนาทีเพื่อระบายคิวที่เหลือจากรอบก่อน งานจากหน้า Dashboard เริ่มผ่าน `after()` โดยมี Cron กู้คืน

การเปิด Auction สร้าง `live_sessions` ทันที แม้ยังไม่มีผู้ชนะ ส่วน Session เก่าที่มีรอบประมูลอยู่แล้วจะถูกเติมให้โดย migration

## ตัวเลขและการคำนวณ

- กำไร = ผลรวมเงินใน `customer_tab_payments` ที่ตรวจผ่าน − (`cost_amount` + `ad_spent` + `shipping_cost`)
- ค่าส่งด้านบนเป็น **ค่าใช้จ่ายของร้าน** ส่วนค่าส่งในบิลเป็นยอดเรียกเก็บจากลูกค้า แยกกันเพื่อไม่คิดต้นทุนซ้ำโดยอัตโนมัติ
- ยอดขาดรวมคือผลรวม `remaining_amount` ของทุกบิลใน Session แบ่งคนที่ยังไม่โอนเลยกับคนที่โอนแล้วแต่ยังไม่ครบ
- สลิปผ่านนับจากรายการรับเงินที่บันทึกสำเร็จ ไม่รวมรูปที่ยังตรวจอยู่หรือถูกปฏิเสธ ยอดโอนเกินยังเป็นเครดิตและนับเป็นเงินรับจริงตามสูตรกำไรที่กำหนด
- คอมเมนต์นับจาก Webhook ที่รับและบันทึกแล้ว โดยกรองเพจและรหัสวิดีโอ/alias ของ Session คนคอมเมนต์นับผู้ส่งไม่ซ้ำและไม่นับตัวเพจ คำดัก/บิดนับคอมเมนต์ที่เข้าเงื่อนไข CF หรือคำสั่งราคา รวมราคาที่ต่ำกว่าขั้นต่ำ ไม่ใช่จำนวนผู้ชนะ
- การคำนวณเงินจริงใช้ PostgreSQL `NUMERIC` ฝั่ง UI บวก/ลบด้วยจำนวนเต็มสตางค์ และปฏิเสธค่าที่มีมากกว่าสองทศนิยม

## แก้ผู้ชนะและยอดบิล

`กำหนดผู้ชนะ` ค้นหาคอมเมนต์ราคาที่รับแล้วในรอบนั้น และใช้ราคาตามหลักฐานที่เลือก สร้างออเดอร์ใหม่ให้ผู้ชนะใหม่ ยกเลิกออเดอร์เดิม แล้วคำนวณ Customer Tab ทั้งสองฝั่งใหม่ใน Transaction เดียว คิดค่าส่งครั้งเดียวและรักษาค่าส่งเฉพาะลูกค้าที่เคยปรับไว้

**เงินที่คนเดิมโอนแล้วไม่ย้ายไปเป็นเงินของผู้ชนะใหม่** สลิปและเครดิตยังอยู่กับเจ้าของเดิม ออเดอร์และลิงก์ชำระเงินเดิมยังผูกกับลูกค้าเดิม จึงไม่เปิดเผยบิลของผู้ชนะใหม่ผ่านลิงก์เก่า ข้อความชนะเดิมไม่ถูกส่งซ้ำอัตโนมัติ หลังแก้ผู้ชนะให้ใช้โมดอลตามยอดเพื่อตรวจและแจ้งยอดใหม่

กดยอดเงินในตารางลูกค้าเพื่อดูหลักฐาน แสดงราคาคอมเมนต์เดิม เวลาคอมเมนต์/ปิดรอบ ยอดเรียกเก็บปัจจุบัน สูตรบวก ค่าส่ง และสลิปที่ผ่าน หาก Webhook ไม่มีเวลาเดิมจะแสดงเวลาที่ระบบรับข้อมูล การปรับราคาไม่เขียนทับหลักฐานราคาเดิม

การบันทึกยอดต้องระบุเหตุผล `ลบยอด` หมายถึงยกเลิกทุกรายการในบิลนั้นและตั้งค่าส่งเป็นศูนย์ ไม่ลบสลิปหรือเงินรับ หากมีรายการ CF จะคืนสต็อกที่เคยตัดไว้เพียงครั้งเดียว รายการที่ยกเลิกแล้วไม่เปิดกลับจากโมดอลนี้ รายการที่จัดส่งแล้วดูหลักฐานได้ แต่แก้ยอดไม่ได้

ทุกคำขอแก้ไขมี UUID สำหรับป้องกันการทำซ้ำ มีเลขเวอร์ชันของบิล/ค่าใช้จ่าย และบันทึกผู้แก้กับ payload ใน `live_session_changes` ถ้ามียอดหรือรายการเปลี่ยนระหว่างเปิดโมดอล ระบบตอบ 409 ให้โหลดใหม่ ไม่บันทึกทับข้อมูล สลิปที่ยังตรวจอยู่และข้อความที่กำลังส่งต้องประมวลผลเสร็จก่อนแก้บิล งานส่งที่ไม่ทราบผลต้องตรวจสอบก่อนเปลี่ยนผู้ชนะ

## พรีวิวและส่งแจ้งยอด

เลือกผู้รับทั้งหมดที่ยังค้างใน Session หรือเฉพาะบิลที่ติ๊กไว้ รองรับ `{name}`, `{due}`, `{paid}`, `{short}`, `{items}` โดย `{due}` แสดงสูตรรวมรายการและค่าส่ง มีพรีวิวแยกรายคน เลขบัญชีจากบิล และตารางยอด/สถานะแจ้งล่าสุด

ส่งผ่าน Messenger โดย Worker ตรวจยอดล่าสุดหลังสร้างข้อความ และแนบบิลจริง เลขบัญชี ลิงก์ชำระเงิน/แนบสลิปเสมอ แม้ Template ไม่ได้ใส่ตัวแปรยอด งานใหม่ไม่เพิ่มซ้ำกับคิวที่ถึงเวลาแล้ว กำลังส่ง หรือรอตรวจผลส่ง แต่สามารถกดแจ้งทันทีได้แม้มีรอบทวงอัตโนมัติในอนาคต

มีโควตาร่วมกัน **12 คนต่อนาทีต่อเพจ** เว้นอย่างน้อย 5 วินาทีหลังจบการส่งแต่ละคน และมีงานส่งพร้อมกันได้หนึ่งคนต่อเพจ จำกัดการกดเข้าคิวจาก Session สามครั้งต่อนาที การปิดแท็บไม่ยกเลิกงานที่เข้าคิวแล้ว ยังคงใช้เงื่อนไข Messenger window, bot pause, opt-out, kill switch และโควตาข้อความเดิม รายการที่ส่งไม่ได้แสดง blocked; ไม่ทราบผลส่งแสดง requires_review และไม่ส่งซ้ำเอง

## ตรวจสอบ

- `npm run test:live-sessions` ทดสอบคำนวณเงิน ขอบเขต API และ Transaction จริงในฐานข้อมูล PostgreSQL จำลอง รวมย้ายผู้ชนะหลังรับเงินบางส่วน ค่าส่งครั้งเดียว เครดิต การคืนสต็อก CF คำขอซ้ำ เวอร์ชันบิล และโควตาส่ง
- `npm run test:live-sessions:ui` ทดสอบโมดอลและฟอร์มบน Chromium ที่ 375/768/1024/1440px โดยใช้ API จำลอง ภาพอยู่ใน `.tmp/session-ui-preview/`
- ผ่านชุดทดสอบประมูล/บิลสะสมเดิม ชุด TypeScript หลัก ชุด schema, Typecheck และ Next production build

การตรวจในเครื่องไม่ได้ส่ง Messenger จริง ไม่ได้รัน migration บนฐานข้อมูล Production และไม่ได้ยืนยันสิทธิ์ Meta/Scheduler ของระบบที่ Deploy อยู่
